# 原始APP能出墨、单线变多线：先恢复相同激励对照

原始提交20b96b0的map_channel_pixels_to_tph有两个独立错误：

1. 将一个8bit字节简化成“非零就喷”，完全丢弃bit位置。
2. 对每个通道同时打开同一地址/分区下的两个domain，而非按喷孔坐标选择一个喷嘴。

M0333N V1.2附页B（印刷36页）中，Add11、S1：
D1的Y=9397.70um，D2的Y=8339.35um，相差1058.35um。D3/D4、D5/D6在各自颜色阵列也有相同的Y差。
因此把同一逻辑点写到一对domain，会复制到两个物理高度，能解释“一条横线变两条”；
这并不单独解释所有三条线现象，也不能证明当前单domain无墨的根因。

本次没有改HC波形或马达，仅增加PRINTER_DIAG_MASK；默认仍为1U<<PRINTER_DIAG_DOMAIN。
新版模式2/3使用mask，日志打印mask。当显式定义mask时，以mask为准，domain不再决定输出位。

## 当前仅做一次原始0x3F激励对照

保存本地宏修改并更新BK分支。编辑printer_diagnostics.h：

```c
#define PRINTER_STARTUP_DIAGNOSTIC 3
#define PRINTER_DIAG_SLOT 40
#define PRINTER_DIAG_MASK 0x3F
```

只重新编译烧录BK；HC维持当前版本。不开APP，不改波形、脉宽、速度、纸张位置或墨盒条件。
这里恢复的是原始独立测试的100B列激励，不是回滚整个APP协议和所有启动测试。
字车行程仍为既有7480步并返回，无自动寻零；沿用此前确认可运行的起始位置。
预期日志mask=0x3F，HC首次非零列data=0x3F、active_bits=6。
这选择六个物理喷嘴，不是“单个黑色像素”，可出现多条线。

发回日志与纸上结果后再决定下一项：
- 若恢复出墨，可逐个domain建立出墨及坐标对应关系，不再把所有domain一起输出当单像素。
- 若仍无墨，说明仅恢复数据掩码未复现旧版，需要继续核对旧版启动流程/驱动状态/机械覆盖范围，不能据此直接认定喷头损坏或改动脉宽。

普通APP图像映射仍未修复：完整BIN解析、MSB-first逐bit解包、附页B地址映射与颜色/左右列位移补偿必须一并核对，不能仅删除旧的单线门闸。
