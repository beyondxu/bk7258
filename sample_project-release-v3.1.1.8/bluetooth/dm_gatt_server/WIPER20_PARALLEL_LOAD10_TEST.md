# 刮刀端20mm往返两轮，字车与10mm进纸并行

BK分支 codex/printer-startup-load-prep，启动标记 APP_SERVICE_CMY_WIPE20_PARLOAD10_V16。
HC32保持eb46357。图像尺寸、正常打印窗口、11034步总行程与匀速参数均保持原值。

## 最终动作

1. APP数据/图像准备通过，喷头关闭，在LEFT刮刀端向行程内部走3740步、返回3740步，
   重复两轮。按7480步约40mm换算，每个单程约20mm；共四腿、约80mm累计路程。
2. 字车用TIMER4向RIGHT做完整无喷墨行程，同时当前任务驱动进纸马达3900脉冲，
   按11700脉冲约30mm换算为10mm。不是“等进完纸再启动字车”。
3. 若字车先到RIGHT，则在那里等待余下进纸；若纸先送完，则等待字车到RIGHT。
   当前两台电机的速度保持原值，没有按视频重新测定共同完成时间。
4. 两项都成功才允许图像行ARM、SYNC和点火。首条图像行从RIGHT反向打印，
   图像控制器根据实际端点选择方向，并使用已有的反向渲染/喷嘴补偿。
   图片不会因此左右镜像；结束时仍无喷墨停回LEFT。

没有再送第二次10mm，没有新增字车10mm；后续正常逐条带进纸保持原来396/397脉冲。
开机仍为一次完整无喷墨往返，不进纸、不做这两轮20mm刮擦。
纸张与字车初始化、刮擦、并行进纸阶段都保持喷头OFF，不存在纸未覆盖时提前点火。
目前由软件脉冲数及返回值判断准备完成，尚无光耦/霍尔反馈，不能据日志证明纸实际覆盖喷嘴。

## 并行与失败处理

没有新增任务或抢占SPI传输。字车脉冲由已有定时器中断发出，U5进纸在主任务中运行；
两台电机使用独立GPIO，保持共同升压供电与U4微步相位。运动中无SPI、无UART日志。
U5新接口motor_page_load_keep_power_guarded逐步检查字车错误；字车中断迟到/定时器错误
则停止进纸，进纸返回错误或短发则停止字车。均不自动回程或继续图像打印。

## 验证

- 真正的TIMER4逻辑模拟验证四腿各3740步、范围0–3740、精确返回、全程零点火。
- 进纸模拟每步推进独立时间，期间字车定时器持续运行，完成后到RIGHT；
  验证进纸未完成时无ARM/SYNC/点火，随后第一条反向行完整发出1180列。
- 覆盖U5提前失败、字车中断迟到，确认停止、位置标为未知且无盲目返程。
- 实际U5函数的停止回调测试在第17脉冲停止，并保留3900脉冲正常加载回归。
- 实际图像控制器从准备后的RIGHT起印，逐像素核对CMY物理位置、连续两页和结束LEFT停放。
- 相关SDK对象编译检查通过；毫米数、机械接触与恢复出墨仍需实机验证。
