# 技术支持补充：单路升压下的能量与频率复核

依据用户于2026-11-10提供的技术支持聊天；当前约束是只使用现有一路升压，不改为VL/VP分开供电。
用户随后确认当前一路电压为15V，因此本轮基准记录为15V/CE1.97us，不再使用旧电压范围作为当前状态。
这是相对能量与代码节奏核算，不是测得的喷嘴电流或实际热量。

## 技术支持给出的参考

| VP | 发热时间参考 | V²t参考量（V²·us） |
|---|---|---|
| 12V | 2us | 288 |
| 12.5V | 1.8..1.9us | 281.25..296.875 |
| 13V | 1.7us | 287.3 |
| 13.5V | 1.6us | 291.6 |
| 15V | 约1.3us，但受采样限制 | 292.5 |

支持还提到VL应满足15..16V；15V下可尝试最小1.6us；S低电平至少0.38us。
前四组的V²t很接近，确实符合近似恒能量调整思路。
以相同电阻、相同有效加热定义估算E∝V²t；CE不一定等于每个电阻真实导通时间，
电压降、电阻、温度和内部驱动未知，所以不能把此比值当作已经测得的墨腔能量。

按此前记录的打印时VP15.9..17.4V和当前CE1.97us计算，V²t≈498..596，
是288参考量的约1.73..2.07倍。此前电压未必还是现在设置，应先确认当前实际值。
即使VP恰为15V，1.97us的参考量也约443，即1.54倍。
这使过高能量成为需优先验证的因素，但没有证明它就是停喷或D1关联的根因。
此前15V到17V曾改善过出墨，这个历史结果也不能忽略；当时喷头状态和时序不同，需控制变量再比较。

## 单路方案的边界

原理图中Q4的VP支路与Q5的VL支路都来自VDD_15V，只有开关，没有独立电压调节。
当前只在这一路中排查：不改线、不外接独立VP，不把共同升压直接降到12V而忽略VL要求。
软件当前只能控制升压开关，不能单独把VP设成12V。

当前基准已由用户确认为15V，先保持15V及CE1.97us完成同地址对照，不继续降低共同电压影响VL。
当前V²t参考量约443，为288参考量的1.54倍；能量因素仍未排除。
这不是已经测得实际加热过量，也不能据此直接解释D1/D2差异。
同地址D1/D2/双选代码保持可用，统计并记录每档真实电压，避免同时改电压和CE。

单路且VL需约15V时，无法直接复现“VL15V、VP12V、CE2us”的独立供电条件。
在15V下按288参考量推算时间约1.28us，但当前四段顺序采样仅最低时间之和就为4*0.38=1.52us，
还未计GPIO等开销，不能为追求1.3us而把S采样压到规格以下或截掉S4。
如后续探索1.6us，也需先核对当前序列是否可实现，不能只据删NOP宣称达到。

## 18kHz与55us

按聊天含义，25个Add加一次清零构成一组完整列处理；18kHz对应同一喷嘴相邻两次发热起点
至少约55.6us，不是要求每个不同Add都额外等待55us。
当前BK每6个电机脉冲发1列，每步高电平4us、巡航低电平260us，
因此请求列间隔下界6*(4+260)=1584us，软件请求频率上界约631Hz；SPI、HC处理、加减速只会进一步延长。
当前每列每地址只按源数据执行一次，故正常请求侧远低于18kHz。

可以排除当前正常代码调度下“单喷嘴请求频率超过18kHz”这一解释。
这不能排除实际信号错误导致的重复触发、未关断或有效加热时间异常。
原有地址/列末停歇保持，不能把25次地址选择错误地当作同一喷嘴连续发热25次。

## 当前优先顺序

1. 当前用户已确认15V，固定此共同档位；不改为分路供电。
2. 在固定档位及CE下，用同地址D1/D2/03与接收CRC排除数据和地址干扰。
3. 依据实际纸面结果再决定供电能量对照、跨S验证或针对D1的电气检查。
