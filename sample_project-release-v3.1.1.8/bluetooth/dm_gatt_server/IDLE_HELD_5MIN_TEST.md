# 单次保电停喷5分钟测试 APP_IDLE_HELD_5MIN_V1

基于task853/854的AB+BA结果：60秒内24条均可见，首条仍可能偏弱/偏色。本项只延长停喷时间，尝试复现历史整条不喷；暂不重复A/B、改变电压/tFire或增加预喷。

## 本次操作

只更新BK到 `codex/printer-idle-held-5min`。HC32保留当前连续CE、已测tFire约1.8us的版本，不需更新。

在BK仓库根目录逐条执行，任何一步报错先停止；本地有修改先保留，不强制覆盖。


按原流程烧录BK、整机重启，启动标签应为 `APP_IDLE_HELD_5MIN_V1`。上电不自动打印。

- 先不擦拭，记录实际是否已擦拭及重启后的等待时间。保持当前电压、喷头、接线和HC32时序不变。
- APP使用之前的有效F2长线图，**触发一次即可**。整轮中间不擦拭、不复位、不拔电、不重复下发。
- 约6分钟完成。5分钟等待阶段电机不动是预期行为，BK日志约每10秒显示剩余时间；APP显示忙不能单独判断死机。
- 纸上共6条：第1、2、3条参考线；保电停喷5分钟；第4、5、6条观察线。第4条是停顿后的首条，重点看完整性、颜色、左端是否缺失、同一条线后段是否恢复，以及第5/6条变化。
- 如果有空白，保留空白位置，不按照可见条数重新编号。

## 软件行为与日志

- 仍复用原第5条带的完整118000字节CMY数据，不换喷嘴、不换点阵。第一次冻结后保持到BK重启；CRC与上次重启前可能不同，但本次6条必须一致。
- `IDLE_AB_BEGIN`仍沿用公共日志前缀，字段现在为 `order=HELD_ONLY scans=6 target_gap_ms=300000`；不会再执行A，也不会下一轮自动变BA。
- 起始正常上电、等待2000ms，连续3条参考；等待前HC32已经完成每列停止和A/D清零。
- 5分钟期间VL、VP、CE和公共升压保持开启，地址/数据处于空闲零状态，不发列SPI；仅停用电机输出，恢复时不重复喷头上下电或GPIO初始化。
- 采用相同AON RTC和有效列ACK边界计时：以REF3末个有效列ACK为锚点，补偿前进至首有效列的时间。OBS1的 `active_gap_ms`应为约300000；允许299900..300100ms，超出返回-12、终止测试并关电。
- 计时不等于直接测量墨滴。目标对齐逻辑、失败收尾、保持电源的走纸API和原始运动参数与60秒版本相同。
- 780脉冲线间距、1560脉冲末尾间距保留，共指令约14mm走纸；实际距离仍需纸面核对。
- 测试结束正常请求喷头OFF并关闭升压；全程一次head ON会话，HC32最终应累计7080列/708000字节，invalid=canceled=0。
- 第二次误触发仍会再做一次相同6条/5分钟测试；不会自动补A组。因此只需触发一次。
