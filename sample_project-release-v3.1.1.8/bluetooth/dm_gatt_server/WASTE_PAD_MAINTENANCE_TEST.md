# V35 废墨海绵定位吐墨清洗

用户已确认现有喷墨行程可到海绵上方、位于海绵范围内。按本次确认，使用现有PRINT_RIGHT右端作为废墨接收点：先在喷墨关闭状态下找GPIO24光耦，再向内退374步（约2mm）停稳，然后才允许维护吐墨。此定位是光耦参考的计步位置，海绵覆盖依据用户实物确认，软件没有检测海绵或覆盖范围的传感器。

开放海绵按废墨接收垫处理，不需要接触喷嘴，也不要求加水。没有看到或确认吸墨泵／软管，因此只执行主动定量吐墨，没有负压吸墨或未定义的机构动作。废墨垫需有适当接墨容量／可维护性；软件请求次数不是实际液体体积或饱和度测量。

## 本次先做一项实机测试

更新BK后，点APP测试页现有“喷墨头清洗”一次。此默认命令现在是**废墨垫清洗，不进纸、不在纸上出图**。观察是否停在海绵上方、墨落在海绵范围内、结束后回到原密封槽。保存`WASTE_POSITION`、`WASTE_FIRED`、`WASTE_DONE`和`MAINT_RESULT`日志。此次不需要重刷HC32（保留79ba462）。

流程：关闭喷墨移动找光耦 → 内退374步 → 停稳 → 分组吐墨 → 关闭喷墨 → 回刮刀侧 → 既有两次慢速擦拭 → 回密封槽并按当前策略停机。没有改变普通图片的喷墨窗口、速度、行程、纸张进给或密封槽停靠位置；普通图片不会自动触发废墨吐墨。

## 定位和喷射边界

- 需要当前字车位置已知并位于原刮刀侧停靠点，OC3已初始化且出发时为HIGH。
- 以既有11221步为寻光耦上限；没有检测到光耦、检测明显过早（少于10473步）、初始LOW、定时异常均不建立吐墨许可。
- 正常触发后停止未来STEP，退374步；确认GPIO24释放为HIGH，计步位置为PRINT_RIGHT，停止并释放TIMER4。整个定位过程喷墨关闭，不进纸。
- 只有维护流程成功建立的专用到位标志允许静止吐墨；普通图像到右端不会自动获得许可。位置未知、位置不匹配、TIMER4仍活动／占用或光耦LOW时拒绝吐墨。
- HC使用现有LBUFv1、673us列周期和有限1180列播放。BK仅启动一次SYNC、等待有限时间后释放，再核对token／CRC／1180列结果；SYNC保持LOW时不发送SPI数据。
- 600喷嘴分12组，每喷嘴请求32个普通点，总19200请求，单列峰值<=8个有效位。数据准备和电气驱动与纸上定量恢复一致；不增加VP、不改变S/tFire、不使用高能量脉冲。
- 吐墨期间无U4／U5 STEP输出。READY／时钟／通信异常时释放SYNC、请求喷墨关闭、撤销到位标志，停止后续组；已开始的组可能已喷出部分点，不自动重试。
- HC原有20us时序余量保护、60us列间空闲保护和有限列数不变。完成喷射之后才返回、擦拭、停靠。

## APP和协议

继续使用类别06、子类08、类型01；APP现有`cleanInkHead()`无需修改即可发出空参数命令。

| 参数 | V35功能 | 需要纸 |
|---|---|---|
| 空参数 | 废墨垫清洗 | 否 |
| 单字节00 | 独立纸上600喷嘴检查 | 是 |
| 单字节01 | 纸上检查→恢复→复查 | 是 |
| 单字节02 | 废墨垫清洗 | 否 |

默认行为与V34不同：V34空参数在纸上出图，V35空参数在海绵处静止吐墨。已报告缺纸不阻止废墨清洗；开盖、墨盒、故障、任务忙碌等前置条件仍保留。将`PRINTER_WASTE_MAINTENANCE=0`可禁止废墨模式（含默认空参数），不会偷偷回退为纸上清洗。

入队应答和完成事件沿用V34：06/08类型02一字节结果；完成06/08类型01`[mode,result]`及标准work状态。入队成功不是已疏通，`WASTE_DONE`／`MAINT_RESULT result=0`表示命令执行完整，实际恢复仍需随后打印检查。

`python3 tools/make_maintenance_command.py clean`生成02废墨清洗帧；`check`生成00；`paper-clean`生成01。工具只生成帧，不自行连接或运行设备。

## 验证和实机限制

- 实际BK定时器／SPI缓存执行代码与模拟HC结合：正确光耦定位后静止播放1180列，逐点核对无U4／U5步数变化，最后可回原刮刀端点。
- 覆盖光耦未触发／初始LOW／提前触发／未释放、寻位IRQ停顿、无许可、CRC拒绝、READY无响应／提前变高、HC列时序失败以及RTC停止；失败不继续下一组。
- 实际废墨任务控制验证12组、19200请求、原剂量、无纸张API、最后擦拭／停靠和各阶段失败清理。
- 原纸上模式、协议互斥／断连、三种模式worker调度、正常缓存扫描／图片worker回归；BK六个SDK ARM对象编译通过。

主机验证不能证明实物海绵覆盖、实际滴量、吸收容量、机械位置或干结恢复。首轮先确认接墨与回位，再用同一张检查图比较清洗后出墨。此功能是恢复措施，不代表闲置密封或干结根因已经解决。
