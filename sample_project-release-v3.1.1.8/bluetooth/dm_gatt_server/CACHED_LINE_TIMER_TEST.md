# 整行缓存与定时打印：V10

旧程序在每列SPI/HC32握手期间停止输出STEP。即使平均速度相近，仍有每列停顿；
之前改变延时、保持U4相位均未满足噪声目标。本版将整行传输移到运动前，运动期间
不调用SPI。它是新的两端协议测试版，需要同时更新BK和HC32，不能只烧BK。

空白扫描也有噪声，说明逐列握手不是全部原因。此改动同时将空白段改为定时IRQ脉冲，
但不能据此保证驱动斩波或机械声消失；速度也从旧值改变，声音变轻可能包含避开共振
区间的效果，不能仅归功于缓存。原理图U4 REF=3.3V、R18/R19=0.82Ω，按规格书约0.50A；
ROSC经33kΩ接地，关断时间约40us。都须核对实装，与样品主板比较，而不是继续猜延时。
样品若不是ATD5984，先确认其型号/REF位置；不同芯片不能直接套用第15脚或此公式。

## 一次测试

1. 两个仓库分别更新 `origin/codex/printer-cached-line-timer`，重新编译烧录。
   先更新HC32的原 `spi_dma.uvprojx` 工程，再更新BK。BK的SDK定时器源文件也有修改，
   必须正常重新构建SDK/应用，不能只替换旧应用对象。
2. 启动确认BK出现 `APP_SERVICE_CMY_BUFFERED_V10`，HC32出现 `LBUFv1 capacity=118000`。
   保持V8/V9的左侧起点及纸张位置，APP发送原来的六条三色图一次。
3. 先比较开头空白往返的声音和平稳性，不必擦拭来判断马达声音。若跳动/碰撞则停止。
   保留 `BUFFERED_SCAN`、`LINE_BUFFER_RESULT`、`HC32 LINE_DONE` 日志及打印照片。

没有旧协议自动回退：缺少LBUFv1能力、CRC错误、缓存不完整时停止，不尝试边走边传。
HC32先升级仍支持旧BK的逐列PCTL协议。GPIO接线、细分111=1/16及行程不变。

## 数据与时序

- 单行1180列，每列100字节，HC32单缓冲118000字节。BK先发BEGIN、全部列、再读状态；
  核对CRC32、token、列数和周期后ARM。下载时没有喷射。
- ARM前检查HC32 200MHz、DWT运行和SysTick空闲。HC32提前完成喷头上电/空闲复位和
  串口输出，再等待行启动。此时D/A为零；非纸区域仍不喷墨。
- BK使用独立硬件TIMER4中断产生STEP，高电平4us、巡航周期120us；仅两端400步
  从1000us加减速。主任务只等待完成，可被调度，不参与逐步延时。不是硬件PWM直出，
  中断迟到仍可能影响边沿；严重迟到立即停止，不丢步数、不追赶补脉冲。
- 第一喷墨位置只拉低一次原SYNC：向右第1790步之前，向左第1796步之前。
  HC32列0立即开始，其余列由SysTick按720us=6*120us播放，共1180列。
  保留原反向颜色偏移和206/200步边界补偿。数据不重复喷。
- HC32 READY在整行执行及等待SYNC释放期间保持LOW；BK停好后释放SYNC，等待HC32
  重新装好状态DMA，再读DONE，核对1180列、token、周期和CRC，才允许下一次进纸。
- BK正常播放期间没有SPI读写。空白条带也使用同一TIMER4扫描，但不ARM、不喷射。
  保留24行条带、396/397步进纸、1590步两侧维护区、10660步总行程、整页U4相位保持。

## 故障与限制

HC32行起点等待超过5秒、SYNC提前释放、列中断迟到超过20us或列执行超期时停止后续
喷射并关闭喷头。BK定时器忙、启动无ACK、步进中断严重迟到或整程超时会停止并使位置
无效；不盲目归位。HC32喷射错误会在该有界行程结束的DONE检查时报错，阻止后续进纸。
现有页面失败锁保持，需重启并恢复已知起点后再试。

两端是独立晶振/定时器，只有行起点同步，并非共享时钟。行末对齐和实际时钟误差必须
实测；不能仅凭计数成功证明位置或出墨。BK记录巡航中断最大间隔（AON日志时钟较粗），
HC32记录DWT的最大迟到和每列周期消耗。不得在噪声验证前继续追求更高速度。

单缓冲使下载期间字车仍需等待，`prepare_us`可量出这个时间；本版不声称消除全部端点
停顿，也不保证电流斩波/机械噪声消失。HC32脉宽、VL/VP电压和必要回填延时不变。

## 软件验证

- `test_buffered_motion.py`：实际BK缓存传输函数、定时步进引擎和HC32缓存状态机；
  1180列完整数据与CRC、两个方向的物理列位置、空白扫描、模拟主任务7ms停顿仍持续
  定时、旧固件/坏CRC/定时器占用时无运动、严重IRQ迟到停止。断言所有SPI均在停止时。
  两个仓库需同处父目录；可用HC32_SOURCE指定HC32的source目录。
- `test_timer_us_api.py`：固定微秒重装值，禁止使用current_count+delay造成周期漂移；
  校验非法/保留/忙通道、回调注册顺序及更新周期的边界。
- HC32 `test_line_cache.py`、`test_line_playback.py`：缓存容量、CRC、版本/状态/数据校验，
  实际SysTick播放1180个固定时刻、取消/迟到/超时/DWT环绕及死时钟/占用定时器拒绝。
- 原页面、映射、双向物理位置、进纸与HC32逐列握手/零复位测试通过。
- BK应用、通信、马达及新SDK timer对象编译通过。HC32整个MDK项目C源使用GCC检查并
  链接通过，约139KB SRAM含8KB栈和8KB堆，低于188KiB主SRAM。GCC验证ELF不是推荐烧录
  镜像；目标Keil编译器和实机时序、噪声、出墨效果仍需本次测试。
