# 原长线与单喷嘴长线：首尾原混色线对照

BK分支 `codex/printer-long-line-control`。只更新BK；HC32保留当前实测CE=1.97us的本地固件。
不调整CE、电压、S采样时间、字车速度、7480步行程、每列6脉冲或尺寸。

依据：新喷头在600喷嘴/每喷嘴16点检查图中无可见墨迹；回到原F2两线版后，
不擦拭为黄线，擦拭后为黑线。说明至少部分三色喷嘴在本机可以出墨，
短线起喷/可见性、喷嘴面状态和数据负载仍需区分，不能直接认定600喷嘴损坏或仅是堵塞。

重新烧录并重启，确认 `APP_LINE_CONTROL`。不要恢复旧诊断头文件。
使用刚才能打印黑线的同一喷头和相同准备方式，任务中不擦拭、不人工干预。
APP发送原 `F2-horizontal-edges.png` 一次。
这次需要原F2数据，不是任意图片仅作触发；三色必须各有至少一个256点以上的长线喷嘴，
且所选条带单列不超过32位，否则执行前拒绝。不能将拒绝任务理解为喷头不出墨。
完整任务约一分钟，5次往返、4次3170脉冲进纸，正常每次扫描后关喷头电源。
准备至少约40mm的可用纸张长度及正常起点边距，不自动出纸。

## 纸面次序

按打印先后应得到：

1. 原第5条带混色线：与先前能出黑线的数据同一路径。
2. 从该条带选取的一个青色喷嘴，保留它原有的全部列墨点。
3. 一个品红喷嘴，保留原列墨点。
4. 一个黄色喷嘴，保留原列墨点。
5. 再打印与第1条逐字节相同的混色线。

每条间进纸3170脉冲，名义约8.13mm。纸面上下顺序以实际走纸方向为准。
不添加文字或额外喷嘴标记。单喷嘴线天然比原混色线细，黄色也较浅，近拍时注意辨认。
单喷嘴由实际点阵选择：每色选点数最多的喷嘴，并在并列最高者中选中央行。
不会补齐缺点、移动横向位置或增加预喷；典型F2数据每色被选喷嘴约895点，
不再像600喷嘴检查那样只喷16点。首尾原线保持整份原始条带，包括其余原喷嘴。

## 日志

`LINE_CONTROL_BEGIN` 给出原条带CRC及总墨点数。
三个 `LINE_CONTROL_PICK` 给出颜色、物理行、地址、S段、数据位和原墨点数。
五个 `LINE_CONTROL_PASS`：`ORIGINAL_CMY,C_ONE,M_ONE,Y_ONE,ORIGINAL_CMY`。
第1和第5条CRC必须相同；全组打印前后均验证原缓冲区和各扫描点阵。
每次扫描仍为1180列、去回各7480脉冲。
结束应为 `LINE_CONTROL_DONE scans=5/5 feeds=4/4`。
HC32仍应每次统计1180列、invalid=canceled=0；墨点数是输入计划，不是物理墨滴检测。
发生通信、短进纸、CRC异常时停止并锁定，不继续盲目运动。

## 判断

先看首尾混色线是否都保持黑色，再解释中间三条：

- 首尾正常且单喷嘴长线正常：这几个喷嘴可在低负载长序列中工作，上一张短线全白不能作为全600喷嘴坏的证据。
- 首尾正常但某单喷嘴长线不正常：聚焦该喷嘴/数据位/S段及选通负载；混色线不能证明组成它的每个喷嘴都正常。
- 首线正常、末线变黄或变淡：喷头/供墨/驱动状态在任务中发生变化，不能只把中间缺失归因于某个地址。
- 首尾也不正常：这次没有建立正常混色线对照，先记录现象，不凭此判定全部单喷嘴失效。

本试验不能单独证明堵塞、气泡或驱动能量的具体原因。
若擦拭伴随拆装喷头，触点接触也可能变化，不能把恢复完全归因于擦拭动作。

## 验证

22项主机测试通过，新增独立规格CSV长线数据测试和实际BIN渲染/五次扫描控制测试。
首尾118000字节分别与正常完整图第5条带比较一致，单喷嘴数据是原位、原点数的严格子集。
覆盖无效/空白/过稀数据、OOM、链路未就绪时无运动，成功后可重复，首/中/末扫描失败、
OFF失败、进纸异常和数据变化后停止锁定。控制器通过Cortex-M33对象编译。
