# 打印异常：排除进度与证据边界

当前阶段：HC32已改为连续CE、25地址加Add25全零停止组；用户反馈实测tFire约1.8us，能够连续打印，但停顿后首条可能不出墨，后续恢复。当前BK已完成首轮自动停喷A/B对照：task852、AB顺序、两组实际ACK停喷间隔均60017ms；数据/计数吻合，照片12条均可见，A首条存在偏浅和可见左端偏短，B首条仍有颜色变化，尚待BA复测，见[IDLE_AB_TEST.md](IDLE_AB_TEST.md)。

此前将CE高电平宽度直接视为tFire的解释已撤销；相邻地址对应S下降沿间隔才是当前核对的tFire。此前基于CE=1.97us计算的V²t不能作为实际加热能量证据。[SUPPORT_ENERGY_REVIEW.md](SUPPORT_ENERGY_REVIEW.md)仅保留为有此限制的历史讨论。下表既有D1/D2关联来自先前测试，不等于新模式已验证。

| 因素 | 当前状态 | 证据与范围 |
|---|---|---|
| APP再次转换导致冻结任务换点阵/换喷嘴 | 已排除为最新冻结任务内的差异来源 | 缓存REUSED、同编号CRC一致；不适用于更早未冻结任务 |
| 当前日志中的整列漏发/取消 | 计数层面未发现 | 每扫描1180列、invalid=canceled=0；不代表每个数据位正确 |
| 正常代码调度下单喷嘴请求频率超过18kHz | 已排除于当前请求流程 | 每6步一列、每步至少264us，列请求间隔至少1584us、频率不超过约631Hz；实际误触发/持续导通未排除 |
| 完全由先后位置决定缺失 | 不能单独解释最新图 | 正反序后仍是D1四条未见、D2四条可见；时间/温度等仍可能参与 |
| 缺失随机且D1/D2等概率 | 证据减弱，未统计排除 | 目前只有少量重复观察，不能证明独立随机性或概率相等 |
| D1与D2测试时地址不同 | 尚未排除，本轮处理 | 在地址2与5分别比较相同S2的01/02/03 |
| BK到HC32接收缓冲区数据不同/整列漏发 | 已排除为task852本轮差异来源 | 单帧CRC6B3BDF59独立重复组合：3帧8F628343、6帧BED31FD8，与HC32吻合；A两次3540列、B7080列，invalid=canceled=0；止于接收缓冲区 |
| HC32到喷头的GPIO/排线/触点路径 | 未排除 | 接收CRC不能验证物理输出，当前D1关联值得重点查 |
| 地址或S段选通问题 | 未排除 | 本轮先同地址S2，必要时下一轮跨S段 |
| 原逐地址切换CE实现符合规格书 | 已否定这一前提 | 正常打印及两种停止/清零图中CE保持高；已修正实现，但不能证明它是所有缺墨的唯一原因 |
| 停顿后首条缺失与重新上电有关 | 证据提示有关，但未定因 | task852 A重新上电后可见首条偏浅/偏短，B保电后首条有线但颜色改变；不能将所有掉色归于重启，需相同60秒BA复测以控制顺序 |
| 驱动能量/动态供电 | 未排除 | 用户新测tFire约1.8us；保持当前电压和时序不变，本轮比较停喷时的供电状态，不继续使用旧CE脉宽估能 |
| 喷嘴面/气泡/补墨状态 | 未排除 | 擦拭及样品机运行后状态会变化；不能仅据此认定堵塞 |

每轮依据实际数据更新“已排除/证据减弱/仍未排除”，不把“程序返回成功”当实际喷墨成功。
CRC匹配的排除范围止于HC32接收缓冲区，不扩展到GPIO电平、喷头内部和墨滴。
