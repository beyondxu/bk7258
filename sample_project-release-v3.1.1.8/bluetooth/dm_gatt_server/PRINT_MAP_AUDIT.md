# 下一阶段：BK生成的100B喷嘴列映射审计（不喷墨）

分支：`codex/printer-map-audit`，基于已完成白图/点/横/竖线数据审计的分支。
用户确认的旧问题是一条黑线变成多条不同颜色的线，不是多条黑线。

## 本次实现

- 新增可移植C模块 `printer_mapper.c/.h`，仅做原生BIN流解析、喷嘴映射和指纹计算，不引用GPIO、SPI或电机驱动。
- BIN采用与APK原生库核对过的TIFF式流解压；按图像命令宽度读取精确的width×24字节，绝不扫描压缩数据中的ESC寻找边界。
- 按列优先、MSB-first逐bit取192行逻辑点，不再将一个字节简化成一个点。
- 按M0333N V1.2印刷36页附页B提取全部600个喷孔坐标，生成200行的地址/Section/左右domain选择表。
- 一个逻辑颜色点只设置一个domain位；不会像旧函数一样同时打开两个相距约1.058mm的喷孔。
- C=D1/D2、M=D3/D4、Y=D5/D6，与规格书印刷8页布局图一致。
- 用每个domain的物理X坐标计算颜色和左右列的触发延迟。采用整数列量化，偏差不超过约半列；测试默认几何下三色残差小于0.2um。
- 为补偿尾部保留额外列，不截断位图，不丢弃边缘点。
- 每个输出列仍为 `address_index*4+section_index` 排列的100字节，与现有HC接收格式一致。
- 审计在线程中运行，定期让出CPU，不阻塞BLE回调；只保留一个条带的三色数据，不必把680KB完整解压内容同时留在PSRAM。

## 必须区分：几何候选与机械标定

默认参数会写入日志：

```text
[MAP_CONFIG] pitch_centi_um=4233 direction=1 first_nozzle=0 reverse_y=0 CANDIDATE_ONLY
```

- `pitch_centi_um=4233`为42.33um/列的候选值，**不是已经测得的马达位移**。
- `direction=1`表示数学模型中物理X递增；实际DIR引脚对应哪一方向仍需确认。
- `first_nozzle=0`表示按物理Y从高到低选前192个喷孔，剩余8个不用。可用0..8调整保护行分配，不自动假定居中4行。
- `reverse_y=0`按物理Y递减排列逻辑行；纸张方向与绝对页原点仍待标定。
- 默认D1..D6延迟分别为0、1、21、22、42、43列。反方向则为43、42、22、21、1、0。

这些参数适用于验证映射结构，**不代表当前机械运动已适配**。1180列图像会生成1223列，原7480步行程不能直接使用，否则可能裁掉补偿数据或改变安全行程。本分支没有启用打印，也没有改变HC加热波形。

若要进入实际喷墨，必须先确认字车扫描方向、每列步数/实际位移、首喷孔及纸张原点、192行走纸量、补偿后的有效行程，再使用验证过的列数据；不能仅关闭审计宏就当作已完成打印。

## 用已捕获BIN离线得到的期望

配置为上述默认值，均为8个192行条带、宽1180、补偿43列，总输出9784列。
表中Y包含白图固有22点，映射保留这些点，不擅自删除APK内容。

| 原BIN | 接收CRC32 | 输入C/M/Y | 输出C/M/Y | 列流CRC32 |
|---|---|---|---|---|
| 白图 | 443DCE67 | 0/0/22 | 0/0/22 | 73074FA1 |
| 单黑点 | 90C3E25E | 1/0/22 | 1/0/22 | AA4E7C8C |
| 黑横线 | F463D710 | 370/254/355 | 370/254/355 | D8A40D97 |
| 黑竖线 | AB25529A | 337/273/348 | 337/273/348 | 6BAD19D8 |

列流CRC定义为按条带、按输出列依次累加：`条带逻辑y(uint32LE) + 输出列号(uint32LE) + 100B喷嘴数据`。
它不是SPI线上附加的协议字段，也不是旧的BIN CRC，而是可重复的映射结果指纹。
只有BIN和配置完全相同时才能比较指纹；新转换若生成不同BIN，需重新导出后再离线比对，不强求固定CRC。

## 当前只需做一次本机映射审计

1. 保存本地改动；在BK仓库执行：
   ```sh
   git fetch origin
   git switch --track origin/codex/printer-map-audit
   ```
   如果本地已存在该分支，则切换后`git pull --ff-only`。
2. 不改诊断头文件：`PRINTER_DATA_AUDIT=1`、`PRINTER_MAP_AUDIT=1`均为默认。
   编译保护会拒绝“开启映射审计但关闭接收审计”的组合，避免误以为关闭审计即可使用新的打印引擎。
3. 原命令重新编译烧录BK；HC固件无需更新。
4. APP设置不变，只发送之前同一张黑横线PNG。
5. 保存从`AUDIT_START`到`AUDIT_RESULT`的日志，其中应新增：
   ```text
   [MAP_CONFIG] ... CANDIDATE_ONLY
   [MAP_AUDIT] swaths=8 width=1180 max_delay=43 columns=9784 crc32=D8A40D97
   [MAP_DOTS] input_CMY=370,254,355 output_CMY=370,254,355 no_physical_print
   ```
   仅当接收BIN CRC仍为F463D710时，上述数值才是对应期望。
6. 设备本轮仍然不出墨、不走纸、不扫描字车。`AUDIT_RESULT PASS`只表示BIN接收审计，需另看`MAP_AUDIT`结果；解析不支持时会明确打印NOT_MAPPED。

无需为了准备本轮重新发送其他三张图，我们已保存并离线验证了它们。

## 验证及复现

从项目目录运行：

```sh
python3 tools/generate_nozzle_table.py --check
python3 tests/test_mapper.py
python3 tests/test_audit_worker.py
python3 tools/map_audit.py path/to/bk_received.bin
```

测试包括：600个坐标完整性；全部576个逻辑颜色行的一点一喷孔；保护行/纵向翻转；两个X方向的三色物理坐标重合；随机图案经独立坐标表反解后逐点相同、无重复无丢点；跨192行边界；压缩/未压缩指纹一致；截断、未知命令、错误配置拒绝。

已用GCC ARM对可移植映射模块做M33编译检查；完整BK固件及设备运行结果仍需本地验证。
旧实际喷射路径暂未接入新映射器，不能把本次审计结果称为已经完成真机黑色合成打印。
