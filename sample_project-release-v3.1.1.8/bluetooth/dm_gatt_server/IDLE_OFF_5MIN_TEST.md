# 单次关电恢复对照 APP_IDLE_OFF_5MIN_V1

保电五分钟task863的第4条仍可见，未复现整条不喷。本项只改变停喷期间的供电条件，查看重新建立喷头与公共升压后，首条是否明显恶化。

## 更新与操作

只更新BK到 `codex/printer-idle-off-5min`，HC32保留已测tFire约1.8us的连续CE版本，不调电压、MOS、S宽度或加预喷。

在BK仓库根目录逐条执行，报错先停止；本地修改先另存或提交，不强制覆盖：

```bash
cd ~/armino/bk_avdk_smp
git fetch origin
git switch codex/printer-idle-off-5min
git pull --ff-only
git log -1 --oneline
cd sample_project-release-v3.1.1.8/bluetooth/dm_gatt_server
make bk7258 SDK_DIR=~/armino/bk_avdk_smp
```

烧录BK、整机重启，启动标签为 `APP_IDLE_OFF_5MIN_V1`；上电不自动运动。先不擦拭，记录实际是否已擦拭、当前电压及等待时间。APP发送之前有效的F2长线图，**只触发一次**，约6分钟完成。中间不复位、不擦拭、不插拔、不重复点击。

纸面顺序：1、2、3条参考；停喷五分钟；4、5、6条观察。保持780脉冲线间距和1560末尾间距，总指令约14mm走纸，真实距离仍需纸面核对。空白也要保留位置，不按可见条数重新编号。

## 软件流程

- 原完整CMY长线、相同物理喷嘴、118000字节缓存；本次六条CRC必须相同。模式 `order=OFF_ONLY scans=6 target_gap_ms=300000`，不再自动运行B，也不在第二次点击时交换模式。
- 初始正常上电、稳定2000ms后打印参考3条，期间不在每条之间重启喷头。
- REF3前进、回程及走纸完成后，正常请求HC32关闭喷头，再关闭公共升压。
- 以REF3末个有效列ACK为锚点，估算恢复前进时间，提前重建升压、打开喷头并稳定2000ms，按共同目标时刻打印OBS1。
- 目标是有效喷射请求之间停喷300秒，不是OFF后另外睡满300秒再上电。实际OFF持续时间略短于300秒，因为回程、走纸、恢复及前进起步均计入停喷间隔。与B使用同样的ACK边界和±100ms容差，OBS1应显示 `active_gap_ms` 约300000。
- 观察3条仍连续打印，结束后关喷头和升压。无预喷，等待/走纸/回程不发列SPI。超时、CRC变化、通信或运动失败立即停止，不盲目补打或强制回程。
- 本次两个ON会话：参考3540列和观察3540列，HC32各自354000字节，接收CRC应相同；不是一个7080列会话。
- 等待采用最多1秒的RTOS睡眠，约10秒输出一次剩余时间；等待期间电机不动是预期，不能只据APP忙判断死机。

## 回传与解释

回传完整6条照片和BK/HC32日志，重点第4条相对参考第2/3条是否变浅、偏色、缺失或完全空白，第5/6条是否恢复。注明有无擦拭、当前电压、人工干预；若前三条参考都异常，不能假定OBS前已恢复。

刷机重启会重新冻结数据，APP转换可能产生少量不同像素。若本次CRC与task863的F280E9E0不同，只能优先比较本次A内部REF/OBS，不能把跨轮照片当作逐点完全一致的定量对照。所有排除结论仍止于日志与实际观察支持的范围。

若本轮仅关电后明显失效，则优先细分升压/喷头电源建立、初始化和热状态，不能直接认定电源器件坏或排除供墨。若关电五分钟也能正常恢复，则停止无休止重复相同长线，下一步评估初次上电首条及更广喷嘴覆盖。
