# task873：正常1/1/1三条均无可见喷墨

用户报告三条均空白。BK完整执行REFERENCE_ONLY/CMY_SHORT，run1/CAPTURED，三条各1180/1180逻辑列，源帧CRC均B161B4CA，任务正常结束code=0。

独立zlib crc32_combine将单帧B161B4CA按118000字节重复3次，得到FDAAC56A，与HC32的354000字节CRC一致。HC32列数3540、fired3540、invalid=canceled=0，六个D域均有数据：10725/8985/10719/8523/10725/8982；D=3F、A=004A2912、S=02。16:26:54.397 ON至16:27:19.958 OFF，三条间未重启喷头。

结论：本轮普通连续三条没有恢复可见喷墨，且不能用未发送/接收空数据或整列丢失解释。`fired`仅表示函数调用路径，不是实际墨滴证明。

与task872对比：1/2/1曾出现首条无墨、末条正常次数仍能出墨；873普通三条均空白。额外双发仍值得验证，但两轮不同初始状态、跨重启且冻结帧CRC不同，不是严格配对实验；不能认定普通剂量永远无效，也不能认定双发已经稳定解决。

用户明确希望通过驱动/启动流程减少人工擦拭，不继续要求拆装或反复长等待。保持时序、电压和现有一路升压不变，不盲目增加喷射次数。

下一项先核实完全不出墨时的喷头实际供电：用万用表测控制MOS之后、靠近喷头接口的VL与VP，对喷头GND，记录上电及打印期间读数。仅升压输出15V或日志power=ON不能证明两路实际到头。需要供电时按现有程序完整触发，可分两次读数，并记录各次是否出墨。读数正常也只排除明显的静态掉电/压降，不等于快速瞬态已经排除。尚无这两项实测读数，供电原因保持未排除。

本记录不修改固件，不增加脉冲能量，不要求擦拭或拆装。时序、动态供电、GPIO实际波形、热/供墨状态等仍未被唯一定位。
