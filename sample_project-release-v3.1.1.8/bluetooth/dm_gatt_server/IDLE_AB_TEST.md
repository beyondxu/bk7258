# 自动停喷 A/B 测试 APP_IDLE_AB_V1

目标：在当前 HC32 连续 CE 协议及实测 tFire≈1.8us 下，比较长时间停喷后，首次缺墨是否与重新上电有关。每次APP触发完成整轮，无需手动等待或切电。

## 版本与条件

- BK启动标签：`APP_IDLE_AB_V1`。
- HC32必须已经是 `codex/printer-continuous-ce` / `7786ad1` 或兼容的本地实测版本。正常上电日志应包含 `CONT_CE_v1 ON CE=HIGH idle=Ax0_Dx0`。本次不修改或重刷HC32，不改变已测得的地址节拍/S延时。
- 保持当前供电、MOS和喷头；整轮中间不擦拭、不插拔、不重新上电。记录本轮开始之前有没有擦拭。
- APP发送原先有效的F2/上下横线图，仍按1180x1476、补齐1536的现有协议校验。不要换成全白、小图或不同格式。
- 第一次从原始第5条带（内部index=4）渲染完整CMY长线，冻结118000字节原始列数据。所有参考、观察、A、B及后续APP触发均复用此缓存，CRC相同；重启BK才重选数据。输入仍需完整有效，换APP图不改变已冻结内容。
- 需要至少256个非零列且CMY均有数据，避免误用短促、稀疏的喷嘴检测图。没有数据/分配失败/通信未就绪均不运动。

## 自动流程及纸面顺序

首次触发：先A后B；下一次触发：先B后A，之后交替。每轮12次扫描，每阶段6次。

| 阶段内纸面顺序 | 打印内容 |
| --- | --- |
| REF 1、2、3 | 同一条原始CMY长线，连续打印，期间不重启喷头 |
| 停喷 | 目标60秒，不发列SPI；纸已提前移动到观察位置 |
| OBS 1、2、3 | 同一条长线，连续打印，不在三条之间重启喷头 |

- A_OFF_RESTART：参考线3之后正常关闭喷头支路，再关闭公共升压；接近恢复时，重建升压、开启喷头、保留原2000ms上电稳定等待，按共同目标时刻开始观察线。
- B_HELD_POWER：参考线3之后不发送任何OFF/ON，不重建GPIO，不改变公共升压。只停用电机输出；HC32已在每列返回前完成停止和A/D全零重置，CE仍高但不喷射。恢复时只唤醒电机。
- 两种模式走纸都用已有 `motor_page_feed_keep_power`，不调用会将升压拉低的普通走纸初始化。前进7480步/回程7480步、1180列及原速度参数不变；回程和走纸不发列数据。
- 每条之间780走纸脉冲（按此前标定约2mm），阶段最后1560脉冲（约4mm），总走纸指令约28mm；真实距离仍需纸面核对。纸面先出现6条第一阶段线，再出现6条第二阶段线。黄色可能很淡；所有位置都保留，不按可见线数量推断编号。
- A、B阶段各自开始前都正常开启喷头并等待2000ms；每阶段结束正常关喷头。整轮结束一定请求喷头OFF并关闭公共升压。

## 60秒如何对齐

不是简单地“OFF后睡60秒、ON后再睡2秒”。

1. 实际运动循环仅在预计算的第一个、最后一个非零列完成传输时读取AON RTC，不扫描像素、不打印日志。时间是成功ACK边界，不声称直接测到了墨滴喷射。
2. 使用REF3最后一个有效列ACK作为停喷锚点，以及REF3前进开始到第一个有效列ACK的时间，估算下一次前进开始时刻。
3. A预留升压、控制握手和2000ms稳定时间，B提前唤醒电机，两者再等待同一目标前进时刻。
4. OBS1日志的 `active_gap_ms` 给出实际两次有效列ACK的间隔，应在59900..60100ms。超出则标记 `IDLE_AB_INVALID`、返回-12、终止整轮并关电，不能当作有效A/B结果。OBS2/3该字段为0，表示不做60秒比较。
5. 60秒等待分成最多1秒的RTOS睡眠，日志约每10秒报告一次剩余时间，不长时间忙等；无自动预喷。

## Git更新与编译

在现有BK仓库根目录（例如 `~/armino/bk_avdk_smp`）逐条执行，任一步报错就停止。若本地诊断头或其他文件有改动，先提交或另存；不要强制覆盖，也不要把旧诊断开关直接重新套用到新模式。

```bash
cd ~/armino/bk_avdk_smp
git fetch origin
git switch codex/printer-idle-ab
git pull --ff-only
git log -1 --oneline
cd sample_project-release-v3.1.1.8/bluetooth/dm_gatt_server
```

按原方法烧录BK，整机重启后确认启动标签。HC32保留当前已测1.8us版本。上电不自动打印；APP触发一次约需3～4分钟，期间保持运行，不重复点击。APP可能仍显示原图，实际输出为固定A/B实验。第二轮需要再触发一次；不要重启BK，否则会回到AB顺序并重选缓存。

## 需要回传

- 一整张纸的清晰照片，注明第几次触发；保留所有空白位置，重点比较每阶段第4条（OBS1），再看第5、6条是否恢复。
- BK从 `IDLE_AB_BEGIN` 到 `IDLE_AB_END` 的完整日志；正常结束 `code=0`，每条CRC一致，OBS1间隔约60000ms。
- HC32同步日志。A的参考和观察分别是两个电源会话，各应累计3540列；B参考和观察是一整个会话，累计7080列。不要要求每条线单独一条ROW_AUDIT。
- 第一次启动测试前是否擦拭，测试过程中有无人工干预，当前电压。

若参考线已经全部缺墨，先如实保留照片；自动程序无法确认参考线实际健康，不能仅凭脉冲和CRC宣布对照有效。

## 解释及验证边界

- A首条差、B正常：优先检查重新上电/升压建立/初始化及保电状态差异；温度等因素仍有影响，不能仅据此认定某段电源电路坏。
- 两者都差、后续恢复：更支持停喷启动相关，仍不能直接认定堵塞或排除能量、供墨。
- 两者正常：60秒或本轮条件未复现；下一步再延长等待。
- 下一轮交换BA以检查顺序影响；第一次的12条不能排除所有随机性。

验证：新增真实BIN渲染+实际运动/电源函数模型检查，覆盖AB/BA、跨APP冻结、计时、保电、短走纸/通信/上电/关电/缓存损坏/超时故障后停止与关电；原26项检查通过；新控制器Cortex-M33编译和生产hw_printer_stub.c使用SDK头文件的目标编译通过。未生成或验证完整SDK链接/刷机固件；实际喷墨、轨电压和走纸距离尚待本机验证。
